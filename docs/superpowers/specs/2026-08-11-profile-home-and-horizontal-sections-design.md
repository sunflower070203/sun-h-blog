# Sunny Blog Profile 首页与横向分区设计说明

日期：2026-08-11
状态：待用户复核
范围：继续修改本地 Demo，不提交、不推送、不部署

## 1. 目标

把当前首页的“科研学习、日常生活、个人介绍”纵向长页面，改成一个接近 GitHub Profile 的个人导航首页。首页只保留本人资料、纵向链接合集和手动 Pin 的文章；三个内容栏目拥有独立 URL，并通过克制的水平滑动动画切换。

## 2. 页面与 URL

- `/`：个人 Profile 首页。
- `/research`：科研学习文章列表。
- `/life`：日常生活文章列表。
- `/about`：完整个人介绍。
- `/posts/:slug`：现有文章详情页，保持不变。
- `/admin/*`：现有单管理员后台，保持不对外开放注册。

右上角公开导航固定为“科研学习、日常生活、个人介绍”。站点名 `Sunny` 返回 `/`，不算第四个栏目。当前页面对应的导航项具有清楚但克制的激活状态。

## 3. Profile 首页

首页采用 GitHub Profile 式信息组织，不再出现三个完整栏目：

- 头像。
- 显示名称。
- 一至两句简短介绍。
- 外部链接合集，从上到下排列。
- Pin 文章区域，最多展示 6 篇。
- 安静的后台入口。

链接不再预设“导师主页”“GitHub”等身份类型。后台填写什么标题，首页就显示什么标题；每一行只包含可选图标占位、链接标题和可选说明。链接保持原有安全规则：仅允许 HTTP/HTTPS，新标签打开，并包含 `noopener noreferrer`。

## 4. Pin 文章

Pin 直接使用现有文章字段 `featured`：

- 后台文章编辑器中现有“精选”开关即 Pin 开关，不新增第二套收藏数据。
- 首页只展示同时满足 `status === "published"` 和 `featured === true` 的文章。
- 最多展示 6 篇，按发布时间从新到旧沿用公开文章接口顺序。
- 草稿即使被标记为精选，也不得出现在公开首页。
- 没有 Pin 文章时显示简短中性空状态，不生成宣传文案。

## 5. 科研学习与日常生活页

`/research` 和 `/life` 使用相同的目录式文章列表组件：

- `/research` 只接受分类精确等于 `科研学习` 的已发布文章。
- `/life` 只接受分类精确等于 `日常生活` 的已发布文章。
- 不从标题、标签或正文猜测分类。
- 页面展示标题、日期、摘要和可选标签。
- 空栏目只显示中性空状态。

## 6. 完整个人介绍页

`/about` 使用单独的富文本内容，不复用首页短简介：

- 首页短简介继续使用 `bio`。
- 完整介绍使用新的 `aboutContent` JSON 文档字段。
- 数据格式沿用文章编辑器现有的 TipTap JSON，不接受任意 HTML 或脚本。
- 支持标题、段落、粗体、斜体、列表、链接、图片和现有图库节点。
- 公开页面沿用文章正文的安全渲染组件和排版规则。
- 未填写时只显示标题和中性空状态。

后台 `/admin/profile` 增加“完整个人介绍”编辑区域。它复用现有富文本编辑能力和图片上传接口，不新建第二套编辑器格式。

## 7. 水平切页交互

三个栏目使用独立路由，而不是把四个页面放进一个超宽横向容器：

- 点击右侧栏目时，新页面从对应方向轻微滑入，旧页面同步淡出。
- 路由顺序定义为：首页 → 科研学习 → 日常生活 → 个人介绍。
- 浏览器返回、前进和直接访问 URL 均能得到正确页面；动画失败不影响导航。
- 动画只作用于公共页面内容区域，固定导航不跟随滑动。
- 动画时长控制在约 220–300ms，不使用弹跳、视差或拖拽切页。
- `prefers-reduced-motion: reduce` 时完全关闭位移和过渡。
- 移动端仍通过点击导航切页，不劫持浏览器的纵向滚动或系统返回手势。

实现优先使用浏览器 View Transition API；不支持时退化为普通路由切换，不增加动画依赖。

## 8. 数据变更

在现有 `site_settings` 单例记录中新增：

- `about_content jsonb NOT NULL`，默认空 TipTap 文档。

共享契约中的公开资料增加 `aboutContent`。公开 `/api/profile` 可以返回该字段，因为它本身就是公开个人介绍；后台壁纸、遮罩和模糊参数继续不得通过公开接口泄露。

数据库变更使用新的增量迁移，不修改或覆盖已存在的个人资料、外观设置、文章和媒体数据。

## 9. 视觉规则

- 保留当前近白背景、近黑正文、低饱和单一强调色和大量留白。
- Profile 首页比内容页更紧凑，链接使用纵向列表，不做大面积卡片墙。
- Pin 文章以 2 列或单列的轻量仓库卡片呈现，移动端自动变为单列。
- 内容页维持期刊目录式文章条目。
- 不出现导师身份说明、学校年级、AI 口号、渐变、轮播或复杂装饰动画。

## 10. 成功标准

1. `/` 不再包含科研、生活和介绍的完整纵向栏目，只显示 Profile、链接和最多 6 篇 Pin 文章。
2. 右上角导航精确指向 `/research`、`/life`、`/about`。
3. 三个 URL 可刷新、前进、后退和直接访问。
4. 支持时切页呈现水平滑动；减少动态效果时没有动画。
5. 科研和生活页严格按现有分类展示文章。
6. 只有已发布且精选的文章出现在首页。
7. 后台可以分别编辑短简介、纵向链接和完整富文本介绍。
8. About 图片继续使用现有本地媒体上传和安全渲染流程。
9. 现有文章、登录、草稿、发布、图片上传和后台外观功能不回归。
10. 本轮只更新本地 Demo，不进行 Git 提交、GitHub 推送、数据库实库迁移或服务器部署。

## 11. 明确不做

- 不实现访客注册、评论、点赞或用户收藏。
- 不让访问者拖拽页面完成横向切换。
- 不把外部网站 iframe 嵌入 About。
- 不复制 GitHub 的颜色、图标和组件代码，只参考其 Profile 信息层级。
- 不创建新的 Pin 数据表或推荐算法。
